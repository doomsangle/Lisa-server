### 1.2 我们**绝对不收集**的信息（红线）
❌ SSH 私钥明文（用户必须自行保管）
❌ 支付密码、信用卡完整 CVV（支付流程走第三方渠道 SDK，本平台数据库零存储）
❌ 人脸图像原始数据（仅在 KYC 时调用服务商 API 做一次性比对，**比对完成后 1 小时内从内存/缓存删除**，不持久化任何原始人脸照片或特征向量）
❌ 生物识别指纹、虹膜、DNA 等敏感个人生物信息
❌ 宗教信仰、政治观点、性取向、工会会员身份等 GDPR 第 9 条「特殊类别数据」（除非法律强制或用户明确书面同意 + 行政备案）
❌ 儿童个人信息（本平台**不向 18 岁以下未成年人提供服务**，注册页强制勾选「我已年满 18 岁」，见第 7.2 条）

## 三、信息存储、传输与安全（对应 6 风险 Ⅱ 类 PIPL 第 51 条 · 加密 + 访问控制）

### 3.1 存储位置与架构（数据离岸架构 · 对应 6 风险 Ⅱ 类）
```
【最终用户（中国大陆/全球）】
          │
          ▼ HTTPS TLS 1.3（仅传输加密后的数据）
  ┌───────────────────────────────┐
  │  L1 接入层（香港 CDN + WAF）  │   Cloudflare 香港节点：DDOS 防护、WAF 规则：SQL 注入/XSS/CC
  └───────────────┬───────────────┘
                  │ 内网 TLS + IP 白名单（仅允许 CF 回源段访问）
                  ▼
  ┌───────────────────────────────┐
  │  L2 应用层（香港阿里云 ECS）  │   物理位置：香港新界粉岭数据中心（Tier III+，ISO 27001 认证）
  │  · metoe_backend app.py       │   SOC 2 Type II 审计报告（年度向付费企业版用户提供）
  │  · metoe.db（SQLite 主库）    │   磁盘级加密：LUKS AES-256 at-rest
  └───────────────┬───────────────┘
                  │ SFTP 公钥认证（无密码登录）+ 每日定时任务
                  ▼
  ┌───────────────────────────────┐
  │  L3 冷备层（双异地）           │   ① 阿里云 OSS 香港（离站冷备，GPG-4096 加密后上传）
  │                               │   ② 腾讯云 COS 新加坡（交叉备份，防单机房故障）
  │                               │   保留周期：每日备份保留 30 天 × 每周备份保留 1 年
  └───────────────────────────────┘
```

### 3.2 加密技术措施（KMS 密钥管理体系 · 已预留 `system_configs.type=secret` 类型）
| 数据类别 | 加密方式 | 密钥管理 |
|---|---|---|
| **KYC 敏感字段**（`id_card_no`、`legal_rep_id_no`、`bank_statement_url`） | **应用层 AES-256-GCM**（加密后再入库）+ 字段级脱敏（返回前端时打码：`440***********0213`） | ⭐ **KMS 三级密钥体系**（预留实现，M5 规模化阶段切换）：<br/>① **根密钥 MK**：HSM 硬件加密机（AWS CloudHSM 香港区域，FIPS 140-2 Level 3），永不暴露明文；<br/>② **密钥加密密钥 KEK**：由 MK 派生，用于加密「数据密钥 DK」；<br/>③ **数据密钥 DK**：每个字段组独立 DK，加密实际明文。密钥轮换周期 90 天自动。 |
| **机密配置项**（`paypal_secret`、`lisa_api_secret`、`smtp_password`、`jwt_secret`） | AES-256-CBC + 独立 KEK（配置项 `system_configs.type='secret'` 已标记） | KMS 加密后存 SQLite；运维人员通过 [Configs.vue](file:///d:/Lisa主机网络建设/metoe/src/views/system/Configs.vue) 仅能看到「*******」掩码，不能明文复制。 |
| **用户密码 / API Key 哈希** | bcrypt(12 rounds)（`$2b$12$...`）—— 单向哈希，不可逆 | 无需密钥；哈希值即使 DB 泄露也无法还原明文。 |
| **传输中（TLS）** | 全站 **HTTPS TLS 1.3**（禁用 TLS 1.0/1.1、禁用 3DES/RC4 弱 cipher）；后端与上游 API（Lisa/PayPal）通信走 mTLS 双向认证 | SSL 证书：Let's Encrypt（90 天自动续期）+ ECC P-256 曲线证书（性能比 RSA 高 5x） |
| **冷备文件**（`metoe.db-YYYYMMDD.sql.gz`） | GPG 4096-bit 非对称加密（`gpg --encrypt --recipient ops@metoe.io`） | 私钥仅离线保管在 YubiKey 硬件 U 盾（2 人分权：CTO + 运维总监各持 1 把，需同时插 Key 才能解密备份）。 |

### 3.4 数据泄露应急响应（Data Breach SLA · GDPR 第 33 条 72h 通报）
**当发生或合理怀疑发生「个人数据泄露」时，执行以下流程（M4 自动化预案）：**
```
T+0h  检测到异常（WAF 告警 + DB 访问突增 + 密钥异常使用）→ CTO + DPO 立即启动应急预案 → 隔离受影响主机
T+4h  内部取证：泄露范围评估（哪些字段？多少用户？）+ 根因分析（SQL 注入 / 内部泄露 / 第三方泄露）
T+24h 初步报告生成（泄露范围、影响人群、初步缓解措施）
T+72h ① 向香港「个人资料私隐专员公署（PCPD）」通报（PDPO 第 38 条）
       ② 如涉及 EEA 用户 ≥ 500 人 → 向欧盟数据保护委员会（EDPB）+ 各国 DPA 通报（GDPR 第 33 条 72 小时时限）
       ③ 如涉及加州用户 → 向加州总检察长通报（CCPA 第 1798.82 条）
T+5d  向受影响用户逐个通知：站内信 + 邮件 + 短信（三通道至少两触达），告知泄露内容、建议措施、我们已采取的补救方案
T+30d 外部安全公司独立审计报告出具 → 公开披露（可在 blog.metoe.io 透明度报告页面下载）
```
> **赔付承诺**：因平台安全措施不到位导致的用户敏感信息泄露（非用户自身原因 / 非不可抗力），平台按「每受影响用户 **最高 ¥10,000**」补偿（超出部分通过网络安全责任险赔付，保单保额 ¥2000 万/年，已预留预算）。

## 四、数据出境、跨境传输与第三方共享（对应 6 风险 Ⅱ 类 PIPL 第 38 条）

### 4.1 数据出境与跨境传输声明
1. **用户知悉并明确同意**：您注册使用本服务时，您提交的所有个人信息（包括 KYC、交易、日志）将被**传输并存储在中华人民共和国香港特别行政区 / 新加坡共和国**的服务器上。
2. **法律关系定性**：因运营主体为**香港公司**（境外主体），您的注册行为构成「**境外数据控制者直接向境外收集信息**」，不适用《个人信息保护法》（PIPL）第 38-43 条关于「**境内运营者**向境外提供数据」的**安全评估 / 标准合同 / 认证**三重路径义务。换言之：
   > 🔑 **合规逻辑**：PIPL 适用大前提是「境内运营者」收集个人信息；MetoE 运营主体为境外（香港），故 PIPL 第 3 条域外管辖原则下仅适用「以向境内自然人提供产品/服务为目的」的有限约束——我们已采取「等效保护措施」（香港 PDPO + GDPR 标准合同条款 SCCs）作为替代合规方案。
3. **跨境传输机制**：
   - 对**欧盟 EEA 用户**：已签署《欧盟委员会标准合同条款（Standard Contractual Clauses, SCCs）》（2021/914 版本，模块 2：控制者→控制者），作为跨境传输的合法性基础。用户可邮件至 `dpo@metoe.io` 索取 SCCs 签署副本。
   - 对**香港本地用户**：适用 PDPO「数据保护原则 8」——跨境传输需目的地具备「至少同等水平的数据保护法规」，新加坡、欧盟、美国均已满足此要求。
   - 对**英国用户**：适用英国国际数据传输协议（IDTA）+ UK GDPR。

### 4.2 第三方共享清单（「除下表所列情形外，**绝不向任何第三方出售、出租、交换**您的个人信息」）
